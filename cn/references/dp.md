# 动态规划

## 讲解时必须依次确定的五件事

按这个顺序推导，**不要跳步直接给转移方程**。

### 1. 状态定义（`dp[...]` 的含义）

用这套流程推：

```
写暴力递归的函数签名 → 参数表就是候选状态
```

然后做两个检验：
- **冻结测试**：只给你状态变量的值（抹掉其他记忆），能继续做决策吗？不能 → 加维度
- **删维度测试**：转移方程里没真正用到的下标 → 删掉

**某个量该进下标还是进值？**
- 必须精确知道（不同取值决定未来能做什么）→ **进下标**
- 只需知道最优值（越大/越小越好，不限制未来）→ **进值**

口诀：**能贪心的量进值，必须精确的量进下标。**
（416 分割等和子集：和要"恰好等于target"，所以和进下标；0/1背包：容量进下标、价值进值）

**"以 i 结尾" vs "前 i 个"**
转移时需要知道**边界元素具体是谁** → 必须钉死结尾。
- 300 LIS：要判断能否接上新元素，必须知道当前序列末尾是谁 → "以 nums[i] 结尾"
- 198 打家劫舍：只需知道"i-1 偷没偷"，这信息已被 dp 的结构编码 → "前 i 个"

**tip**：`dp[i]` 的 i 尽量用**长度**（0..n）而非下标（0..n-1），`i=0` 自然表示"空"，边界最干净。

### 2. 转移方程

问：**这个状态能从哪些前驱状态来？** 或反过来：**最后一步操作是什么？**

- 线性 DP 问"最后一个元素怎么处理"
- 区间 DP 问"最后一次操作在哪"（枚举分割点）

⚠️ **"更小的子问题"不一定是 `i-1`**：
- 279 完全平方数：`i - j²`
- 322 零钱兑换：`i - coin`
- 338 比特位计数：`i >> 1` 或 `i & (i-1)`

### 3. 边界

让 `i=0`（或空区间）有明确、不歧义的含义。常见：
- `dp[0] = 0`（凑出0需要0个）
- `dp[0] = 1`（凑出0有1种方案——什么都不选，这个1是所有方案的种子）
- 布尔型：`dp[0] = True`
- 求最小值时初始化为 `inf`（`inf` 天然表示"不可达"，且会一路传递下来）

### 4. 遍历顺序

**依赖决定顺序：依赖谁就先算谁。**

| 类型 | 遍历方式 |
|---|---|
| 线性 | 下标从小到大 |
| 背包 | 见下方"背包两个正交维度" |
| 网格 | 行、列都正序 |
| **区间** | **按区间长度从小到大**（依赖更短的内部区间） |
| 双串 | 两个下标都正序 |

### 5. 答案在哪

- "以 i 结尾"型：答案常是 `max(dp)` 而非 `dp[n-1]`（300 LIS、53、152）
- "前 i 个"型：答案是 `dp[n]`
- 区间型：`dp[0][n-1]`

## 五大类速查

| 类型 | 状态 | 代表题 |
|---|---|---|
| 线性 | `dp[i]` | 300 LIS、152 乘积、53、198 |
| 背包 | `dp[j]` 容量 | 416、322、279、518 |
| 网格 | `dp[i][j]` 行列 | 62、64、63 |
| 区间 | `dp[i][j]` 区间 | 5 回文、312 戳气球、241 |
| 双串 | `dp[i][j]` 两串下标 | 72 编辑距离、1143 LCS |

**网格 vs 双串**：都是 `dp[i][j]` 但含义不同——网格是行列坐标（从上/左转移），双串是两串各自的进度（看末尾字符是否匹配）。

## 背包：两个正交维度

**维度一：每个物品能用几次 → 决定内层容量的遍历方向**

| | 0/1 背包（用一次） | 完全背包（无限用） |
|---|---|---|
| 内层容量 | **倒序** | **正序** |

**倒序的原因**：一维 `dp[j] = f(dp[j], dp[j-w])` 中，`dp[j-w]` 必须是"上一行的旧值"（还没放当前物品）。正序会让它被本轮更新过、已含当前物品 → 物品被重复使用。

**二维版没有这个问题**（两行物理分开），正序倒序都对 → **先写二维理清逻辑，确认对了再压一维。**

**维度二：求什么 → 决定两层循环的嵌套顺序**

| | 求最优值（min/max） | 求方案数 |
|---|---|---|
| 循环顺序 | 随便 | **外层物品、内层容量**（得组合数） |

外层物品保证物品使用顺序固定，`1+5` 和 `5+1` 只算一次 → 组合数。
外层容量会算成排列数（377 组合总和IV 恰好要排列数，就用外层容量）。

## 区间 DP 的两种形态

**① 剥首尾**（5 最长回文子串）
`dp[i][j] = (s[i]==s[j]) and dp[i+1][j-1]`

**② 枚举分割点**（312 戳气球、241 运算优先级、08.14 布尔运算）
枚举"最后执行的那次操作" k，把区间劈成 `[i,k-1]` 和 `[k+1,j]`。
标准三重循环：**长度 → 起点 → 分割点**。

⚠️ 有些区间 DP 的 dp 值要**同时记多个量**（08.14 要同时记"得0的方案数"和"得1的方案数"），因为合并时都要用。

## 空间优化：滚动数组的方向判断

**看你复用的那个小下标值，应该来自哪一行：**
- **要上一行的旧值 → 倒序**（0/1 背包）
- **要本行的新值 → 正序**（网格 62/64、双串 72/1143）

⚠️ **压一维后，"只有单一来源"的边界容易被内层循环跳过**。
（64 最小路径和：内层 j 从1开始，漏了每行第一列的 `dp[0] += grid[i][0]`）

⚠️ 依赖**左上角** `dp[i-1][j-1]` 的双串 DP，压一维时要用临时变量 `prev` 存住它（它会被本行更新覆盖）。

---

## 什么 DP 能优化时间

- **能**：有额外可利用的结构。LIS 有单调性 → 二分把 O(n²) 降到 O(n log n)
- **不能**：本质二次问题。编辑距离/LCS 有理论下界（SETH），网格路径也是。只能压空间

**判断法则**：看有没有可利用的额外结构（单调性、值域有界性）。

## 记忆化搜索 ↔ 自底向上

**同一个 DP 的两种实现。** 转换方法：
- 递归函数的参数 → dp 数组的下标
- 递归的依赖关系 → 循环的遍历顺序

记忆化按需计算（只算用得到的状态），递推全部填表。区间 DP 用记忆化递归往往更好写（自动处理"按长度递推"）。

## 该用 DP 还是别的

| 求什么 | 用什么 |
|---|---|
| 所有具体方案 | **回溯** |
| 能否/计数/最优值 | **DP** |
| 局部最优能导向全局最优 | **贪心**（DP 会 TLE 时考虑） |

例：131 分割回文串（求所有分割）用回溯，139 单词拆分（求能否）用 DP。

**DP → 贪心的坍缩**：当"某个量的精确值不重要、只有它的极值影响未来"时，DP 可坍缩成贪心（435 无重叠区间：DP 是 O(n²) 会 TLE，按右端点排序贪心是 O(n log n)）。

## 常见踩坑

- 答案取 `dp[n-1]` 而非 `max(dp)`（"以i结尾"型的经典错误）
- 0/1 背包用了正序 → 物品被重复使用
- 求方案数时用了外层容量 → 算成了排列数
- 压一维后漏了边界的单独更新
- 多状态互相依赖时先更新了一个再算另一个（152 必须先存三个候选再更新 max/min）
