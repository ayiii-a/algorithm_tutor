# 栈与队列

## 讲解时先问一句：栈里存什么

这个问题一问，用哪种立刻归位。

| 栈里存什么 | 哪种用法 | 例题 |
|---|---|---|
| **下标**，维持递增/递减 | ① 单调栈 | 739、901、84、42、496 |
| 每一步的**聚合量** | ② 辅助栈 | 155 最小栈 |
| **进入嵌套前的现场** | ③ 嵌套解析栈 | 394、20、32、224 |
| 元素本身，但要换进出顺序 | ④ 双栈模拟 | 232、225、03.05 |
| **待访问节点** | ⑤ 迭代遍历 | 94/144/145、105 |

## ① 单调栈

**识别信号**：找左边/右边**第一个更大/更小**的元素。

**方向口诀**：找更大 → 栈**递减**；找更小 → 栈**递增**。（栈的单调性和你要找的方向**相反**）

```python
stack = []
for i in range(n):
    while stack and nums[stack[-1]] < nums[i]:   # 找更大 → 递减栈
        j = stack.pop()
        # 结算 j：此时 i 就是 j 右边第一个更大的
    stack.append(i)
```

**存下标不存值**（算距离要下标，值可由下标反查）。

**弹出时结算什么，三个难度层次**（讲解时要点明属于哪层）：

| 层次 | 结算内容 | 例题 |
|---|---|---|
| 只用**一侧**信息 | 下标差 | 739 每日温度 |
| 栈内携带**聚合量** | 累加跨度（栈存 `(值, 跨度)`） | 901 股票跨度 |
| 用**双侧**信息 | `高 × (右边界 - 左边界 - 1)` | **84 柱状图最大矩形**、42 接雨水 |

**84 的四个要点**（最难的单调栈题）：
- 递增栈（找左右第一个更矮）
- 弹出时：`高 = heights[弹出]`，`右边界 = i`，`左边界 = 弹出后的新栈顶`，`宽 = i - stack[-1] - 1`
- **末尾加高度0的哨兵**强制清空栈
- 摊还 O(n)：每个下标进出栈各一次

## ② 辅助栈

**识别信号**：一个栈，但要求 min/max 查询也是 **O(1)**。

主栈 + 辅助栈**同步 push/pop**，辅助栈顶永远是当前的最小/最大值。
**核心：push 时就预维护好，pop 时自动回退到上一个状态。**

优化版：只在 `val <= min_stack[-1]` 时才压入（⚠️ 用 `<=` 而非 `<`，否则重复的最小值会漏）。

---

## ③ 嵌套解析栈

**识别信号**：括号、嵌套、配对结构。

**栈里存"进入括号前的现场"**：遇开符号压栈+清空当前，遇闭符号弹栈+把内层结果合并回外层。

**递归与栈解法完全等价**（递归的调用栈 = 你手动维护的栈）。

**32 最长有效括号**（hard，比 20 难得多）：
不只判断是否有效，要求**最长连续有效段**，涉及"跨越已闭合子串的连接"。
推荐**栈存下标 + 栈底放哨兵 `-1`**：遇 `(` 入栈；遇 `)` 弹栈，弹后栈空则当前 `)` 入栈当新哨兵，否则 `max_len = max(max_len, i - stack[-1])`。

## ④ 双栈模拟（两种玩法）

| 题 | 玩法 | 何时倒栈 |
|---|---|---|
| 232/03.04 用栈实现队列 | **批量反转**（两次反转=恢复原序） | out 空了才倒 → **摊还 O(1)** |
| 03.05 栈排序 | **逐个插入**（栈上的插入排序） | 每次 push 都倒 → 维持有序 |

03.05 的设计权衡：**把代价压在 push（O(n)），换取 pop/peek 的 O(1)**。这和 155 最小栈、146 LRU 是同一种"根据操作频率决定复杂度压在读还是写"的思想。

## 常见踩坑

- 单调栈用 `if` 而非 `while`（应该弹出所有不满足单调性的）
- 单调性方向搞反
- 84 的宽度算成 `i - j + 1`（应该是 `i - stack[-1] - 1`）
- 忘记末尾哨兵，栈里残留元素没结算
- 最小栈的优化版用了 `<` 而非 `<=`
