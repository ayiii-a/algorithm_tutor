# 图论

## 讲解时先确定三件事

### 1. 怎么建图

输入常是**边列表** `[[a,b], ...]`，要先转成**邻接表**。

⚠️ **方向别搞反**：`[a, b]` 如果读作"a 依赖 b"，画成 `b → a`（前置指向后继）：
```python
graph[b].append(a)
indegree[a] += 1
```
方向反了，"入度"的含义就变了，整个算法崩掉。**这是拓扑排序最高频的低级错误。**

### 2. 用 BFS 还是 DFS

| 需求 | 用 |
|---|---|
| **最短路**（无权图） | **BFS**（按层扩展，第一次到达即最短） |
| 判连通/可达 | 都行 |
| 找所有路径 | DFS + 回溯 |
| 拓扑排序 | 都行（Kahn 是 BFS，三色标记是 DFS） |
| **图很大/很深** | **BFS**（DFS 递归深度 10⁵ 会爆栈，Python 限制 1000） |

### 3. visited 要不要撤销

> **找"所有路径" → 要撤销**（这条路不通，但别的路可能经过这格）
> **找"连通性/最短路" → 不撤销**（访问过就永久标记）

## 拓扑排序

**问题转化**：能否完成所有任务 ⟺ 有向图**是否有环**（无环 = DAG）。

### BFS / Kahn（推荐）

1. 建图 + 统计每个节点的**入度**
2. 所有入度为 0 的入队
3. 出队一个 → 把它指向的后继入度 -1 → 减到 0 就入队
4. **`finished == 节点总数`** → 无环

**入度的含义：还有几个前置没满足，减到 0 才能开始。**
有环时，环上节点的入度**永远减不到 0**，进不了队列，所以 `finished` 会小于总数。

**附带产出**：出队顺序就是一个合法的拓扑序（210 直接用）。

### DFS 三色标记

- `0` 未访问 / `1` **访问中（灰）** / `2` 已完成（黑）
- **撞到"访问中(1)"的节点 → 有环**（绕回了当前路径上的祖先）
- "已完成(2)" = 记忆化，防止重复探索退化成指数级

**灰 ≠ 黑 是判环的灵魂**：只有当前 DFS 路径上的节点被再次遇到才算环；遇到已彻底走完的黑节点只是"不同路径汇合"，不是环。

## 并查集（Union-Find）

**识别信号**：动态判断连通性、合并集合、检测无向图的环。

```python
def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])    # 路径压缩
    return parent[x]

def union(x, y):
    rx, ry = find(x), find(y)
    if rx == ry: return False           # 已连通（无向图中说明成环）
    parent[rx] = ry
    return True
```

配合**按秩合并**近似 O(1)。适用：547 省份数量、200 岛屿（也可DFS）、684 冗余连接、990 等式方程。

## 常见踩坑

- 建图方向反了
- 忘记 `visited` → 自环/环导致死循环
- 有向图当成无向图（两个方向都建边）
- `start == target` 的边界
- 大图用递归 DFS 爆栈
