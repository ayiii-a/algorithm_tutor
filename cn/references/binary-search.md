# 二分查找

## 本质认知（讲解时先说清这个）

> **二分不要求整个数组有序，只要求：在每个 mid 处能 O(1) 判断答案在哪一半。**

方向信息可以来自：全局有序 / 哪半有序 / 局部趋势（上坡下坡）/ 答案空间的单调性。

---

## 讲解时必须确定的四件事

### 1. 二分的对象是什么

| 二分什么 | 场景 | 例题 |
|---|---|---|
| **数组下标** | 有序数组找值/边界 | 34、35、704 |
| **哪半有序** | 旋转数组 | 33、153 |
| **局部趋势** | 找峰值（数组无序） | 162、852 |
| **答案的取值范围** | **二分答案**（最常见的进阶形态） | 875、1011、410 |
| **值域** | 找重复数、第k小 | 287 |
| **分割线位置** | 两数组中位数 | 4 |

**二分答案的标志**：题目问"最小的最大值"、"最大的最小值"、"最少需要多少X"，且**给定一个候选答案能 O(n) 判定可行性**。

### 2. 选哪套模板（不能混搭！）

| | 闭区间模板 | 收缩到单点模板 |
|---|---|---|
| 初始 | `right = n-1` | `right = n-1` |
| 循环 | `while left <= right` | `while left < right` |
| 收缩 | `right = mid - 1` | `right = mid` |
| 返回 | 循环内返回 或 `left` | `left`（此时 `left == right`） |
| 用于 | mid 可被排除 | **mid 本身可能是答案** |

**关键判断：问自己"mid 还可能是答案吗？"**
- 能排除（已经比较过、不等于target）→ `mid ± 1`
- **可能就是答案**（找峰值、找边界）→ **`right = mid`**，配 `while left < right`

⚠️ **混搭是最常见的 bug**：`right = n` + `while left < right` + `right = mid - 1` 会漏解或死循环。

### 3. mid 的计算与越界

- `mid = left + (right - left) // 2` 防溢出（C++/Java 必需，Python 养成习惯）
- **如果循环体内访问 `arr[mid+1]`，`right` 必须初始化为 `n-1`**（否则 mid 取到 n-1 时越界）

### 4. 边界的等号

找边界时，**命中 target 后不要停，继续往目标方向挤**：
- 左边界：命中后 `right = mid - 1`
- 右边界：命中后 `left = mid + 1`

**±0.5 技巧**（整数数组）：找 `target-0.5` 的插入点 = 左边界，`target+0.5` = 右边界，避开相等分支。更稳的整数版用 `target+1`。本质等价于 `bisect_left` / `bisect_right`。

## ⚠️ 二分失效场景（重复元素）

**重复元素会破坏二分的判断依据**，讲到相关题目时必须点出：

| 破坏了什么 | 应对 | 例题 |
|---|---|---|
| 让 `nums[i]-i` 不再单调 | **放弃二分**，退回 O(n) 线性扫描 | 08.03 魔术索引 |
| `arr[left]==arr[mid]` 无法判断哪半有序 | 保守 `left += 1`，或两边都搜，最坏 O(n) | 81、10.03 |

**额外难点：找最小索引时**
> **"找任意一个"和"找第一个"的剪枝力度不同。** 找任意一个，确认 target 在某半就能丢掉另一半；找第一个，**即使右半有，左半也必须先查**（左半索引更小）。

## 二分答案的写法

```python
def check(x):
    """给定候选答案 x，判断是否可行。必须关于 x 单调。"""
    ...

lo, hi = 最小可能答案, 最大可能答案
while lo < hi:
    mid = (lo + hi) // 2
    if check(mid):
        hi = mid          # 可行，尝试更小/更优
    else:
        lo = mid + 1
return lo
```

**讲解时要说清两点**：
1. **答案的取值范围**是什么（lo、hi 怎么定）
2. **判定函数的单调性**：为什么 `check(x)` 为真则 `check(x+1)` 也为真（或反之）

---

## 常见踩坑

- **模板混搭**（最高频）
- `right = mid` 却用了 `while left <= right` → 死循环
- 访问 `arr[mid+1]` 但 `right = n` → 越界
- 找边界时命中就返回 → 得到任意一个而非第一个
- 重复元素时硬套无重复的模板
- 忘记 target 不存在的情况（返回 -1 或插入位置）
