# 数据结构设计

## 三条核心哲学

**① 单一结构满足不了所有需求时，多结构组合，每个负责它最擅长的操作。**
（146 LRU：哈希表 O(1) 定位 + 双向链表 O(1) 维护顺序）

**② 慢查询不要等到查询时才算，在数据变化的每一刻就预维护好。**
（155 最小栈：push 时就把"当前最小值"算好压进辅助栈）

**③ 根据操作频率，决定把复杂度压在读还是写。**
（03.05 栈排序：push O(n) 换 pop/peek O(1)）

---

## 讲解时的推导顺序

1. **列出所有操作和要求的复杂度** → 这是约束
2. **逐个分析：哪个操作用朴素结构会慢？** → 找到矛盾点
3. **为那个慢操作配一个辅助结构** → 组合
4. **检查：新结构会不会让其他操作变慢？** → 权衡
5. **明确每个操作要同步维护哪些结构**（最容易漏的地方）

## 树状数组（BIT）

**识别信号**：需要**动态插入** + **查询前缀和/排名**。静态前缀和数组插入要 O(n) 重算，BIT 让两者都是 O(log n)。

```python
def update(i, delta):          # 下标从 1 开始！
    while i <= n:
        tree[i] += delta
        i += i & (-i)          # 跳到父节点

def query(i):                  # 前缀和 [1, i]
    total = 0
    while i > 0:
        total += tree[i]
        i -= i & (-i)          # 跳到前一段
    return total
```

`i & (-i)` 取最低位的 1，决定每个节点管辖的区间长度。**下标必须从 1 开始**（0 会死循环）。

## 146 LRU 的四个必踩坑

1. **节点里要存 key**（逐出时从链表拿到节点，要用 key 反查哈希表删条目）
2. **逐出时两个结构都要删**（链表摘除 + `del cache[key]`）
3. **`get` 也要更新顺序**（LRU 的 U = Used，读取也算使用）
4. **逐出时机和判断符号必须配套**：先删后插用 `>=`，先插后删用 `>`
