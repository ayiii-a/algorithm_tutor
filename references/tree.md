# 二叉树

## 讲解时先判断属于哪种模式

| 特征 | 模式 |
|---|---|
| 从遍历序列/有序数组构造树 | **分治建树** |
| BST + 查找/后继/第k小/LCA | **BST 导航**（利用左小右大） |
| 求树的某个属性（深度/直径/路径和/是否平衡） | **树形递归：返回值汇总** |
| 判断子树/子结构 | **树形递归：双函数分工** |
| 树 + 其他技巧 | 前缀和、回溯、哈希 |

---

## 模式一：分治建树

**核心：确定"根是谁" + "左右子树的范围"，然后递归。**

| 题 | 根怎么选 | 左右范围 |
|---|---|---|
| 105 前序+中序 | 前序数组当前位置 | 中序里根的左边/右边 |
| 106 中序+后序 | 后序**尾部** | 同上（pre_idx 反向推进，**先建右子树**） |
| 04.02/108 有序数组→平衡BST | **数组中点**（保证平衡=最小高度） | 中点左半/右半 |
| 109 有序链表→BST | 链表中点（快慢指针） | 中点前/后 |

**105 的两个关键**：
1. 哈希表存中序的"值→下标"，否则每层 `index()` 线性扫描退化到 O(n²)
2. **必须先建左子树再建右子树**（pre_idx 沿前序单向推进，顺序反了整棵树错位）

---

## 模式二：BST 导航

> **BST 的核心性质：中序遍历 = 升序。** 凡是能转化成"按值的顺序"的操作，都能 O(h) 导航，而非 O(n) 遍历。

**导航模板**（以找中序后继为例——即"比 p 大的最小值"）：
```python
while cur:
    if cur.val > p.val:
        successor = cur      # 可能是答案，记下，往左找更小的候选
        cur = cur.left
    else:
        cur = cur.right      # 不够大，往右
```

**⚠️ 为什么只有中序能这样？**

| 遍历 | 与 BST 值大小的关系 | 找后继 |
|---|---|---|
| **中序** | **= 升序**，与值一一对应 | **O(h) 大小导航** |
| 前序/后序 | 顺序由**树结构**决定，与值无关 | 只能 O(n) 模拟遍历 |

**这解释了为什么"BST 中序后继"是经典题而前序后序不是。**

其他 BST 导航题：700 搜索、701 插入、235 BST的LCA、230 第k小、98 验证BST。

## 模式三：树形递归的两种组织

### ① 单函数 + 返回值汇总（后序）

先递归左右子树，再根据左右结果决定当前返回什么。

**236 LCA 是典范**：
```python
if root is None or root == p or root == q: return root
left = lca(root.left); right = lca(root.right)
if left and right: return root          # p、q 分居两侧 → 当前是 LCA
return left if left else right
```
**返回值一物多用**：既表示"我找到了 p/q"，又表示"我就是 LCA"。`root == p` 提前返回自然处理了"节点是自己的祖先"。

同族（都是"先递归左右、再合并成当前返回值"）：124 最大路径和、543 直径、110 平衡、337 打家劫舍III。
**讲这类题时要说清"返回值携带什么信息向上传"。**

### ② 双函数分工

- **外层**：遍历树**找起点**，用 `or`（某处匹配即可）
- **内层**：从起点**判匹配**，用 `and`（处处相同才行）

572/04.10 检查子树是典范。⚠️ 注意区分"子树"（必须一路到叶子完全相同）和"子结构"（B 是 A 的一部分即可）——两者的空节点处理不同。

## 模式四：序列化（+ 子串匹配）

把树转成唯一字符串，判子树变成判子串。**三个必踩的坑**：

1. **数字不加分隔符** → `12` 和 `1,2` 粘连误判 → 每个值加 `,` 前缀
2. **不标记空节点** → 不同结构序列化相同 → 空节点标 `N`
3. **空节点标记不完整** → 匹配到"部分子树"而非完整子树 → 完整标记所有空孩子

**一句话：序列化要做到"唯一且自带边界"。** 分隔符统一写在循环开头最清爽。
（`s2 in s1` 最坏 O(mn)，真要 O(m+n) 需 KMP）

## 模式五：树 + 其他技巧

- **树 + 前缀和 + 哈希**（437/04.12 路径总和III）：把"从根到当前节点的和"当前缀和，`prefix_count.get(cur_sum - target)` 查询。⚠️ **递归返回前要 `prefix_count[cur_sum] -= 1`**（回溯移除，前缀和只对当前分支的子孙有效）
- **树 + 回溯**（113 路径总和II、257 所有路径）
- **树 + 动态候选集回溯**（04.09 BST序列）

## 迭代遍历（栈）

递归改迭代时，栈里存的是"待访问节点"或"从根向下的路径"。
- 中序迭代：一路向左入栈 → 弹出访问 → 转向右
- 105 的迭代解法：栈维护"当前左边界路径"，中序指针判断何时停止向左、转而向右

## 常见踩坑

- 105 忘记用哈希表 → O(n²)
- 105/106 建树顺序反了
- 递归没有处理 `root is None`
- 求"以i结尾"类属性时答案取错位置
- 树高很大时递归爆栈（Python 限制 1000）→ 考虑迭代
