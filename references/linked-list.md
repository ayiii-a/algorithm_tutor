# 链表

## 三大基本功

1. **dummy 哨兵节点**：不存数据的头节点，省掉"第一个节点特殊处理"的所有麻烦
2. **快慢指针**：找中点(876)、找环入口(142)、删倒数第k个(19)、判环
3. **反转链表**(206)：三指针 `prev / cur / next`

**很多进阶题就是这三个的组合**：
- 234 回文链表 = 快慢找中点 + 反转后半 + 双指针比较
- 143 重排链表 = 快慢找中点 + 反转后半 + 交叉合并
- 148 排序链表 = 快慢找中点 + 归并

---

## 讲解时的关键提醒

### 边遍历边改指针：先存 next 再改

```python
nxt = cur.next        # 先存住！
cur.next = ...        # 再改
cur = nxt
```
不先存就会丢失遍历路径。

### 重排后必须检查：尾节点 next 置 None

**这是链表 bug 的头号来源**（死循环、超时都可能是它）。重排后某条链的尾节点，它的 `next` 可能还指向原链表里的某个节点 → **成环**。

### 原地删除节点的标准模式

```python
if 要删除 cur:
    prev.next = cur.next
    cur = prev.next        # prev 不动（后面接了新节点）
else:
    prev = cur             # 保留，prev 前进
    cur = cur.next
```
**"删则 prev 不动、留则 prev 前进"** —— 写错这个是 02.04 分割链表之类题目的常见 bug。

### 快慢指针找中点的两种停法

- `while fast and fast.next`：slow 停在**中点**（偶数时偏右）
- `while fast.next and fast.next.next`：slow 停在**中点前一个**（偶数时偏左）

**148 排序链表必须用第二种**（`fast = head.next` 起步），否则单节点时切不动会死循环。

## 分流与合并

**把节点分成几组时，开几条新链分别收集、最后拼接**，远比在原链上原地挪指针清晰。每条链一个 dummy + 一个尾指针。

（但如果用户已经写了原地抽取的版本且正确，不要强行改成双链——两者都对。）

**合并两个有序链**（21）是 148、23 的基础操作，要写熟。

## 经典题的核心

| 题 | 核心 |
|---|---|
| 138 随机链表复制 | 哈希表 `old→new` / **节点交织 O(1)空间**（copy 插在原节点后，`cur.next.random = cur.random.next`） |
| 148 排序链表 | 归并（合并只改指针，消掉归并唯一的缺点）。归并是**顺序访问结构的排序王者** |
| 23 合并K个链表 | 分治 O(kn·logk) / 最小堆（⚠️ 堆里存 `(val, i, node)`，**i 是平局裁判**，防止比较 ListNode 报 TypeError） |
| 142 环形链表II | Floyd 判圈：相遇后一个指针回起点，同速走，再次相遇即环入口 |

## 常见踩坑

- 忘记 dummy，第一个节点的处理写一堆特判
- 改指针前没存 next
- 重排后尾节点没断开 → 成环
- 原地删除时 prev 的前进时机错
- 快慢指针的起点/停止条件选错导致死循环
